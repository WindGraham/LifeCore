# 通知线程延续设计方案（三方案会审综合）

> 2026-09-17 · 由三个独立 subagent 会审合成（UX 形态 / 数据管道 / Android 能力），逐条验证过 LifeCore 现状代码
> 核心理念（UX 报告一句话）：**通知当门铃，事项流当档案，延续性做进通知的"身份"（同 id/引用条/代际）而非文案。**

## 0. 需求到设计落点

| 需求（用户原话要点） | 设计落点 |
|---|---|
| 有新消息自动弹通知，传递要简洁 | WS 长连 + root 关 Doze → 秒级到达；通知 = 标题（议题+代际角标）+ 两行正文 + ≤3 动词按钮 |
| 核心 agent 对通道任务有历史记忆 | hermes 每通道独立会话（已有）+ 新 MCP 工具 `thread_history`（续报时主动查"上次你说稍后"） |
| 对系统运行、用户最近在做什么有了解 | 状态块注入（已有）+ 决议写回 running_items（闭环，P2） |
| 回复选项后，后续消息继承历史 | notify_threads 表 + 同 notification id 续命 + snooze 到期自动带决议链晋升 |

## 1. 形态选型（UX）

**混合**：通知卡片 = 唯一打断面（单活动锁决定一次只推一条）；App 内 = 按**事项（议题）聚合的单一时间流**。
明确否决：按通道分线程做主界面（AI 汇报不是聊天，用户记忆按议题组织而非按通道）。

通知模板：标题 `📌 议题名（第N次跟进）`（≤20 字）；正文两行 = 结论 + 依据；动作 ≤3 个且用动词文案（"加入日历" > "做"），第三格永远"稍后▾"；展开层（BigTextStyle）放前文时间线；TTS 只念标题+一行结论。

Snooze：三档预设（30 分钟 / 今晚 20:00 / 明早 8:00）。**到期复用同一 notification id 更新原通知**，首行插"上次你说'稍后'，现在有更新"——锁屏上同一条通知"活了过来"。

延续性视觉（可叠加）：① 灰色引用条（"周二 21:04 · 你选了'稍后'"）② 左侧同色竖线串联同议题生命周期 ③ 代际角标 ②③。

**反模式清单**：每条事件独立通知刷屏；通道式聊天主界面；snooze 到期发全新通知（上下文断裂头号元凶）；通知塞完整对话历史；动作按钮 >3 或"选项 1/2"式文案。

## 2. 数据模型与管道（架构）

### 线程模型
`thread_key` 派生（resolve_thread_key，优先级从高到低）：
① payload.thread_key（核心显式指定）② payload.pointer 命名空间前缀（`wx:8832:chat123`→`wx:8832`，同群天然归并）③ channels.session_discriminator（列已存在）④ 兜底 `ch:{channel_id}`。

### 表结构（P1）
```sql
CREATE TABLE notify_threads(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  thread_key TEXT NOT NULL UNIQUE,
  channel_id TEXT NOT NULL,
  title TEXT NOT NULL DEFAULT '',          -- 首条 summary，核心可 MCP 回填
  last_resolution TEXT,
  last_resolved_at REAL,
  last_item_id INTEGER,
  item_count INTEGER NOT NULL DEFAULT 1,
  snoozed_until REAL,
  updated_at REAL NOT NULL
);
ALTER TABLE notify_items ADD COLUMN thread_id INTEGER REFERENCES notify_threads(id);
ALTER TABLE notify_items ADD COLUMN kind TEXT NOT NULL DEFAULT 'normal';  -- normal|resume
CREATE INDEX idx_items_thread ON notify_items(thread_id, id);
```
snooze 不落 state 新值：仍 `resolved/snoozed`，闹钟记 `notify_threads.snoozed_until`，到期生成 `kind='resume'` 新 item 重新入队。**决议即历史，不建新表。**

入队流程（enqueue_notify 改造）：解析 key → UPSERT 线程头（item_count+1）→ INSERT item 带 thread_id；feedback 端点回写 last_resolution/last_resolved_at。

`thread_history(tid, n)`（MCP 与 App 共用）：最近 n 条 item 的 summary/resolution 时间序；决议链 = resolution IS NOT NULL 的序列 → "上次你说稍后/已办"。

### 上下文注入（与 hermes 会话记忆的分工）
- hermes 会话 = 原文与推理层（level/pointer/summary 全文）
- lifecore notify 层 = 用户决议事实层（结构化、App 也要用）
- 冗余边界：pointer/summary 只在 events+hermes 会话；resolution/snooze 只在 notify_*；lifecore 只注入"决议事实"，不重放原文、不塞 pre_llm hook（那里已有六清单）

两条注入路（hermes 零修改）：
① 被动——核心续报时调新 MCP 工具 `thread_history(thread_key, n)` 自己拼"上次你说稍后→现在…"
② 主动——snooze 到期晋升时 lifecore 向该通道 route 转发合成 webhook `{thread_key, summary:"[续报]…", last_resolution}`；subscribe prompt 加 `{thread_key}` 是 lifecore 侧参数，不动 hermes 本体

手机端只带轻量 thread_ctx；完整历史走新端点。

### snooze 语义
计时者：lifecore-server 进程内 asyncio 后台循环 30s 扫描（单进程单 writer 无竞态）。
到期晋升 re_promote()（promote_notify 同源）：扫 snoozed_until<=now → 生成 kind='resume' item（state='queued'，summary 前缀 [续报]，snoozed_until 置 NULL）→ promote_notify()；resume 的 options 由 thread_history 拼入上次决议一句。
幂等防重：晋升前查同 thread 已有 queued/awaiting 则跳过；schedule 去重复用 lists 表：`snooze` 时写 `schedule/resume:{thread_id}`（value 含 fire_at），晋升器只认到期且 resume: 前缀条目，与用户其他调度隔离，fire 后 resolve。

## 3. Android 实现（系统能力评估，root Pixel / Android 17）

及时性：轮询在 Doze 下退化为分钟级，必须换 **WebSocket 长连**（wss 过 nginx，心跳 15-25s，proxy_read_timeout ≥ 2 倍心跳）。
root 三件套（7×24 秒达关键）：`dumpsys deviceidle disable`（整机关 Doze）+ `dumpsys deviceidle whitelist +<pkg>`（已有）+ `settings put global app_standby_enabled 0`。

通知呈现：**MessagingStyle**（每 AI 条目 = addMessage(text, ts, aiPerson)，通知内保留最近 3~5 条，全量历史在 App 内）；预设选项用 Action 按钮 ≤3 个（setSemanticAction），优于 RemoteInput；全屏意图（FSI）对普通 App 已死，用高 importance channel heads-up；隐私 = 锁屏 PRIVATE + setPublicVersion 脱敏副本。

点击流：PendingIntent FLAG_IMMUTABLE + App Links/URL scheme deep link（pathPattern /thread/*）+ singleTask + setAutoCancel。

FGS 时限暗坑：`dataSync` 类型 Android 15+ 每天限 6 小时；**mediaPlayback 不计配额且 TTS 播报恰是合规场景**——主服务挂 mediaPlayback。targetSdk 34 是当前稳妥点，暂缓升 35/36。OTA 后 root 开关需重放。

## 4. 三期演进

| 期 | 内容 | 验收标准 |
|---|---|---|
| **P1 最小可用**（只动 notify 层） | 建 notify_threads + 2 列 + resolve_thread_key + enqueue/feedback 接线；App 线程页（按议题聚合的单时间流）+ 前台服务轮询本地弹通知 | 同群 3 条消息只出现一个议题卡片；选"稍后"30 分钟后原通知带历史复活 |
| **P2 完整体验** | WS 长连 + 关 Doze；MessagingStyle + 动词按钮 + deep link；list_mcp 加 thread_history；subscribe 模板加 {thread_key}；re_promote() + schedule 去重；决议写回 running_items；App 切长轮询/WS | 息屏秒级弹通知；核心续报亲口说"上次你说稍后→现在…" |
| **P3 智能压缩** | notify_threads 加 digest 列（核心 MCP 写回或离线任务）；历史超 N 条折叠；SQLite FTS5 检索 | 长线程不膨胀，秒级回查 |
