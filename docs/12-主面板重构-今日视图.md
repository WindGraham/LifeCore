# LifeCore Android · 产品体验重塑报告
**「从 App 找 AI」→「AI 找 App」**

> 范围：仅改 App 侧 + BFF 增量（不触碰 Hermes 核心）
> 公理沿用 docs/06：App 只对 BFF `/v2/*`；安全/凭证/契约面零妥协

---

## 0. 一句话判断

LifeCore 现在是**「五等分的远程终端」**：会话/通知/通道/任务/设置平铺，五个 tab 同样重要同样沉默。用户不打开 App 它就死，打开也不知该点哪个。**真正的智能 App 不该让用户"找入口"，而应在正确时间把对的卡片送到对的表面**。

---

## 1. 现状五个反用户体验

**1.1 App 不会主动找我。** 所有信息流靠通知 + WS 推，但通知是被动的——只有 agent 真有"待决策"时才有内容。没有"今日值得看一眼"的入口。错过 agent 已做完的整理，下次开 App 又翻历史。

**1.2 5 个 tab 找不到入口。** 五个 tab 结构对称 = 没有优先级。实际频次严重不均：会话（偶尔）/ 通知（一天 3-5 次）/ 通道·任务（配完即忘）/ 设置（月一）。真正高频的"主动 AI 反馈"被埋在第 2 个 tab——等同把"今日头条"塞进"设置"隔壁。

**1.3 通知丰富，静下来不知该干什么。** NotifyFragment 顶部 active 卡片 + 中间收件箱 + 底部排队 TextView。但 `Fragments1.kt:147` `if (o == null) card.visibility = View.GONE`——多数时候 active 是 none，剩空列表 + "队列空"。**App 最常见的状态也是最无聊的状态**。空闲态应是产品主场，不是空场。

**1.4 会话 tab 是历史档案不是入口。** SessionsFragment 平铺所有 session，只有标题+时间。没有任何"继续上次""今天问什么"引导。**主动提问这个最强动作被埋到二级页面**——转化漏斗断在第一屏。

**1.5 通道/任务两个 tab 对 90% 用户是噪音。** 它们是配置面不是消费面，却和会话、通知平起平坐占底栏。配置应藏到汉堡菜单/长按才出——而不是和"今天 AI 干了啥"抢屏幕。

---

## 2. 三个「主动卡片/今日视图」重设计

**核心思路**：首页从「五等分导航」改为「今日」单页 + 抽屉式次级导航。会话、通知、通道、任务、设置下沉为抽屉项。今日页承担「AI 主动找我」的主场。

**卡片 A 「今天已为你做完」**（顶部 always visible，约屏 35%）
数据源：BFF 新增 `GET /v2/digest/today`，agent 周期聚合"今日完成/发现"摘要，每条 ≤ 2 行。
形态：一行总览 + 5–10 条事件条（`✓` 已完成 / `!` 警示色边框待你看）+ 底部「展开全部」「让 AI 总结成一句话」。
交互：点条目跳 thread detail 或 session；「让 AI 总结」调 `/v2/digest/today/summarize` 流式回话。
**反对**：不要无限滚动 timeline。5–15 条最舒服。

**卡片 B 「现在需要你拍板」**（中部，仅 active 非空时显示）
**有且仅有一张**。决策疲劳是反模式——一屏只问一件事。
形态：标题（⏱ 触发时间）+ AI 已起草内容 + 四按钮 `直接发送/改一下/我自己回/稍后`，对应 `/v2/notify/items/{id}/feedback`。「改一下」直接开 inline 编辑（不跳页），编辑完按钮变"发送修改版"。
**反对**：不要卡片堆叠。

**卡片 C 「想问点什么」**（底部永远显示）
数据源：`GET /v2/prompts/suggested?context=digest+time+location`，返回 3–5 个当下语境建议。
形态：3–5 个 chip（点 → 填输入框预编辑，不直发）+ 输入框 + 三按钮 `🎙/📎/📍`。
**反对**：不要开放式 prompt 模板市场。3–5 个随时间变化、与 digest 上下文相关，够了。

## 3. 快输入：第一期做什么

**3.1 语音 → 第一期必做。** sherpa-onnx 已在架构（docs/06 §2）。输入框 🎙 长按起录（流式 ASR，文字实时上屏）；唤醒词「Hey, AI」可选（前台服务 KWS 命中弹动态卡"听到了要发给 agent 吗？"）；决策卡"是/否/稍后"用 KWS 关键词 spotting，< 200ms 离线可用。
**反对**：不要"按住整个 App 都能说"。**只在输入框 + 决策卡**两个表面允许。

**3.2 截屏/分享意图 → 第一期必做。** Android Share Sheet 接 LifeCore 等于零成本拿上下文。`AndroidManifest.xml` 注册 `SEND` + `SEND_MULTIPLE`，mime 白名单文本/图片/PDF。收到分享 → 直接跳今日页 + 输入框预填（文本直接填；图片/PDF 上传 `POST /v2/attachments`，显示 `📎 xxx [已附加]` + 前缀"基于这张图"）。**不弹模态**——分享即明确意图。系统级截屏 OCR 也走这条（截屏通知→点开→SEND text/plain）。
**反对**：不要"分享前选通道/session/目标"。

**3.3 位置 → 第二期。** 暴露成本高。**只在用户主动点 📍 时取一次**（`getLastLocation` 单次，不订阅），作为消息 prefix 不入存储。后台订阅 = 不允许。

**3.4 桌面快捷方式/App Actions → 第二期。** 长按图标 → 「问今天/继续上次/看 inbox」。

## 4. Glance UI / 锁屏 / 通知的层次

**三层定义（反对"什么都弹通知"）**：

- **L0 静默入队**：agent 完成后台任务/普通汇报。**不弹通知**，落入 inbox。
- **L1 通知中心**：新 thread / snooze 到时 / 已读回执。标准通知无声音。
- **L2 抬头**：`notify.active` 决策 / 安全事件 / 唤醒词命中。Heads-up + TTS（前台服务预渲染音频），必须当下处理。

**反模式**：把"AI 完成了一件事"全做 L1。**L0 是主力**——90% 安静入队，开 App 在卡片 A 集中呈现。通知栏不是 timeline。

**第一期不做完整 Glance widget**（缓存难、被系统节流）。替代：锁屏 Live Notification（MessagingStyle 续命 + 锁屏大按钮"查看今日"，深链 `lifecore://today`）。**第二期**再做 4×2 Glance 卡片。**先确保通知层次对了再加**。

**反对**：通知按时间倒序全弹；每条都 TTS；同 thread 不分组（`setGroup` 必填）。

## 5. App 与核心 agent 的角色边界

**原则**：App = 表皮（输入面 + 决策面 + 隐私面）；核心 agent = 大脑（理解、推理、任务执行、跨服务编排）。**不让 App 假装能干 agent 的活，也不强迫用户为小事绕到核心**。

**App 必须自己做的（隐私/即时/手势）**：语音 → 文字（C 级不出端 + 零延迟）；截屏/分享意图接住（系统手势级行为，agent 跨进程不可达）；设备指纹/凭证管理（本地 Keystore，agent 即便被攻陷也拿不到）；通知已读/代际标记（UI 状态不该 round-trip）；决策按钮反馈（< 200ms，前端乐观更新）；位置单次取用（点击即同意，后台订阅 = 不允许）。

**必须"问核心 agent"的**：今日总结（跨 inbox + 日历 + 邮件排序）；起草消息/邮件（LLM 推理）；跨通道任务（跨 registrar + notify + list_manager）；复杂多轮对话；自动化任务编排（任务页只是 CRUD）。

**边界判定口诀**：**"离线/断网/凭证失效时仍要能用的功能放 App；否则放 agent。"** 例外：纯本地缓存展示（已实现的 session 列表缓存）即使离线也要能看。

```
┌──────────────────────────────────────┐
│  今日页（重写 MainActivity）           │
│  ┌─ 卡片A: 今天已为你做完 ─┐         │
│  ├─ 卡片B: 现在需要你拍板 ─┤         │
│  └─ 卡片C: 想问点什么 ─────┘         │

```

抽屉内容按使用频次降序：通知 inbox（原 tab2）· 会话（原 tab1，默认"新对话"+ 历史折叠）· 通道 · 任务 · 设置 · 设备管理（从设置提到一级）。**底栏消失**，tab bar 占的 ~56dp 还给内容区，垂直空间 +15%。

## 7. 反对的反模式

1. 底栏 5 tab 等权重——配置面与消费面必须分离。
2. 通知当 timeline——通知是状态机事件，不是 feed。
3. 空状态显示"暂无数据"——空状态是产品主场，必须给建议/入口/prompt。
4. 长滚动列表——每屏 < 10 行，密度优先于信息量。
5. "打开 App 就要决策"——决策卡片有就显示，没有就给"做了什么 + 能做什么"。
6. 让 App 假装会推理——App 只渲染，推理必须回流 BFF。
7. 静默收集位置/通讯录/日历全量——任何数据获取必须用户当下点的那一次。
8. 多卡片决策——同屏最多 1 张「待拍板」卡。

## 9. 客户端实现备注

- 卡片复用 `MaterialCardView`，不引第三方卡片库。
- 抽屉用 `ModalNavigationDrawer`；旧 `BottomNavigationView` 整套删除（`activity_main.xml` 重写）。
- Share intent 入口：`MainActivity.onCreate` + `onNewIntent` 都进今日页，prefill 走 intent extras。
- 通知层次：三个 `NotificationChannel`（`digest_silent` / `digest_heads_up` / `decision_urgent`），在 `PairActivity` 配对完成时一次建好。
- 决策卡片 inline 编辑用 `TextInputLayout` 内嵌 `MaterialCardView`，不开新 Activity。

---

**总判断**：LifeCore 当前是「能用的远程终端」，不是「智能助理 App」。改造核心是把首页从"导航中枢"变成"AI 主场"。技术实现 90% 复用现有 BFF 端点 + 仅增加 `/v2/digest/today` 一个聚合接口，**对核心零侵入**——正是 docs/06 公理四"App 迭代不动核心"的兑现。
